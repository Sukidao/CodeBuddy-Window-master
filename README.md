# CodeBuddy 窗口书签

给 CodeBuddy IDE（也支持 WorkBuddy / Trae CN / VS Code）用的**项目窗口书签管理器**：
像浏览器书签一样管理常用的项目目录，一键全部打开，也能把已经在跑的窗口直接切到最前面。

- 绿色单文件，**65 KB**，不需要安装、不联网、不写入注册表以外的任何地方
- Windows 10 / 11 开箱即用（系统自带 .NET Framework 4.8）
- 支持本地文件夹、`.code-workspace` 工作区，以及 **SSH / WSL / 容器远程窗口**

## 功能

**书签管理**
- 从当前打开的窗口导入、手动添加文件夹、支持把文件夹直接**拖进窗口**
- 双击打开单个、勾选后批量打开、一键全部打开
- 重命名（`F2`）、拖拽排序（`↑` `↓` 按钮）、删除、搜索过滤
- 按名称 / 最近打开 / 手动排序
- 路径失效时右键「重新定位到…」直接改路径，不用删了重加

**窗口状态感知**
- 每 5 秒自动刷新（可关闭），实时显示每个书签的 **已打开 / 未打开 / 路径失效**
- 点击已经打开的窗口 → **直接把它置顶**，不会重复开一个新窗口
- 右键「关闭这个窗口」可以直接关掉对应的 IDE 窗口
- 底部单独列出「**未加入书签的窗口**」，一键收进书签

**体验**
- 托盘常驻：最小化到通知区，右键菜单直接列出所有书签和未加书签的窗口
- 开机自动启动（可选，启动后静默进托盘）
- 记住窗口大小、位置、列宽和深色模式（跟随系统）
- 深色 / 浅色主题，可在托盘菜单里切换

## 快捷键

| 按键 | 作用 |
|---|---|
| `F5` | 刷新 |
| `Ctrl + F` | 定位搜索框 |
| `Ctrl + V` | 粘贴路径 / 文件夹为书签 |
| `F2` | 重命名选中行 |
| `Enter` | 打开选中行 |
| `Delete` | 删除选中行 |
| `Ctrl + A` | 全选勾选 |
| `Esc` | 清空搜索 |

## 使用

1. 双击 `CodeBuddyWindowMaster.exe`
2. 第一次打开如果列表为空：点「导入当前窗口」把正在运行的窗口收进来，或用「添加文件夹」选项目目录
3. 以后勾选需要的项目 → 点「打开选中」；想全开就点「全部打开」

程序只读取 IDE 自己的状态文件（`%APPDATA%\CodeBuddy CN\User\globalStorage\storage.json`）来判断哪些窗口正在运行，
不读取代码内容，不上传任何数据。

## 从源码编译

不需要 Visual Studio，只要系统自带的 `csc.exe`：

```bat
build.bat        :: 编译出 CodeBuddyWindowMaster.exe
package.bat      :: 编译 + 打包 dist\ 和便携版 zip
```

源码：`src/CodeBuddyBookmarks.cs`（C# / WinForms，单文件程序）

## 数据文件

都在 exe 同目录，可以随意备份或删除：

| 文件 | 内容 |
|---|---|
| `bookmarks.json` | 书签列表（自动保存，另存一份 `bookmarks.json.bak`） |
| `ui-state.json` | 窗口大小位置、列宽、深色模式、排序方式 |
| `error.log` | 仅在出错时生成 |

## 常见问题

**提示“找不到 CodeBuddy 的可执行文件”？**
程序会按 常见安装目录 → 注册表 App Paths → 卸载信息 → 开始菜单快捷方式 的顺序查找，
装在极特殊的位置时可能识别不到，可以把 IDE 路径反馈给我。

**换电脑后书签还能用吗？**
书签里存的是绝对路径，换机后需要重新添加；程序本身只复制 exe 即可运行。

**和 IDE 自带的“恢复上次窗口”有什么区别？**
IDE 自带的恢复在重启或崩溃时不一定可靠，且只能恢复“上一次”的窗口。
这里的书签是持久化的清单，可以挑选、排序、命名，也能管理平时不开但偶尔要用的项目。
